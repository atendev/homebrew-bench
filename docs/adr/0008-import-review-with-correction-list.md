# The SRD import fixes upstream faults through a checked-in correction list and gates fixtures on review

The import reviews every monster it converts and writes an import review list on each run. Entries come in four classes. (a) A structured field contradicts the stat block's own prose, or ability prose self-references a different creature name (such as `mule` carrying Octopus abilities that read `"The octopus..."`); prose wins for field-vs-prose mismatches, per the monster schema decision. (b) A structured field is missing that the prose implies, such as the lost recharge on the second breath of dual-breath dragons or a missing `damage` array when an attack's `Hit:` clause specifies damage (zero-damage attacks such as the Roper's `Tentacle` grapple are not flagged). (c) The stat block contradicts a ruleset table, such as the Archmage printing CR 12 with XP 8,000 while the SRD p. 256 table gives 8,400; the table wins. The prose-wins rule covers class (a) only. (d) A classification note recording where each ability landed (modeled, partly modeled, inert, unmodeled) and its default resolution, plus spell ids missing from the engine's spell effects file.

Only classes (a) through (c) block. A stat block becomes a fixture when it has zero open mismatches. Fixtures graduate one monster at a time, the engine only ever sees fixtures, and the goal is all 341 entries. Classification notes are informational and never block.

The importer never corrects anything on its own. Prose parsing exists only to detect mismatches, never to produce data, and an ambiguous parse produces no entry. Every fix comes from one of two human-written sources: a correction in `data/srd/corrections.json`, or an entry in the hand-authored effects layer for mechanics the text carries. A correction names the monster id, the dotted field path (the same dotted paths the override commands use), the corrected value, a short reason, a citation, and the upstream commit it was written against. The import applies each correction verbatim and writes every application to the review list. After an upstream data bump, a correction that no longer matches anything fails the import outright.

The review list is a generated `data/srd/import-review.md` with a JSON twin, regenerated on every run and committed, so an upstream bump shows its effect as a git diff. The import script prints a summary and exits non-zero while any blocking entry is open.

## Considered options

- Derive values from confident prose parses and apply them automatically. Rejected because deviations from upstream would then live in two places, only one of them human-readable. One checked-in correction file is the single auditable record.
- Treat classification notes as blocking. Rejected because they have nothing to fix; the default resolutions from the effect vocabulary ADR already give unmodeled and inert abilities engine behavior.
- Extend prose-wins to class (c). Rejected because the table is the general rule the engine uses for XP budgets, and the Archmage's 8,000 disagrees with the 2014 printing of the same stat block, which also gave 8,400.

## Consequences

- A fresh upstream bump can fail the import on stale corrections until a human prunes the file. This is deliberate.
- For swap-style `Multiattack` abilities (`"makes N <X> attacks. It can replace K attack(s) with <Y>"`, 34 entries in 2024 SRD), the converter (target design, ticket 036) folds `5e-database`'s `(N - K)` unconditional attacks plus `choose 1 of [K <X>, <Y>]` encoding into a fixed `Action { X, N-K }` step plus a `Choice` of `[X(1), Y(1)]` with count K (see ADR 0005), and resolves spell display names in `action_options` against the monster's `Spellcasting` block (preserving any `(level N version)` note from prose). `data/srd/corrections.json` patches only genuine upstream `Multiattack` faults (`dryad`, `erinyes`), plus one representability exception: the `hydra`'s "Number of Heads" Bite count becomes the starting five Bites with an agent clause for heads lost or regrown, so the engine over-deals once a head dies unless the agent overrides the count. The 10 non-hybrid werebeast form blocks were dropped from the list in ticket 028: their structured options already name only the form's own actions, and the shared prose naming other forms' attacks is a desc quirk the converter never reads, so nothing needs patching.
- Two exact sentences upstream has no field for are read as data, an exception to "never to produce data". The Flyby and Agile sentence becomes the `no_provoke` effect (ticket 054, ADR 0015). "The <creature> can't take this action again until the start of its next turn" becomes `usage: cooldown_until_next_turn` (ticket 058, 44 SRD legendary actions), and each one writes a class (d) note to the review list, so the review stays the auditable record. A correction is for an upstream fault, and here there is none to patch: 5e-database has no usage type for the rule, so 44 identical corrections would only bury the real ones. If the same action also carries a structured usage, the import records a class (a) mismatch and keeps the structured one.
- The import review checks only that spell ids a monster references exist upstream. Authoring and checking the spell effects file is its own ticket.
- Where fixtures ship and how releases carry them belongs to the packaging ticket, not this one.
