# Live spell casts reuse `bench action`, with a cast card to read first

Ticket 003 of the spell-testing map ([Live spell casting prompts](../../.plan/closed/003-live-spell-casting-prompts.md)) decided how a spell reaches the table in live mode for both sides. The answer adds one read-only command and a few start-time checks, and no new pending prompt.

## Considered options

- **A `bench cast` command with no stat block action.** Rejected. The action economy, slot use and usage limits already live on the stat block, and a second path would need all of them again.
- **A new `cast` pending prompt asking for target, slot level and upcast.** Rejected. ADR 0004 keeps targets and slot on the command, and prompts for reactions and dice only. The agent asks the user in chat.
- **The agent renders the spell card by hand.** Rejected. A homebrew entry lives in a user file, and a paraphrase drops clause text.
- **A generic spell list on the monster that the agent picks from.** Rejected. It adds a choice the engine can't check.
- **Adding a spell to a running encounter.** Rejected. Replay and the tamper check depend on entries copied into state at `bench start`, which is the encounter's creation in ADR 0021.
- **A new trigger for a homebrew reaction spell.** Rejected. ADRs 0018 and 0019 limit the trigger vocabulary.

## Consequences

- **Casting.** Either side casts through `bench action <actor> <action-id> <target-id>... [--slot N]`, on a stat block action with a `cast` effect naming the homebrew id. For a PC the agent adds that action to the stat block when the user wants the spell, and for a monster it adds it to the encounter's copy. Both are shown to the user before `bench start`. A monster casts at the stat block's `slot_level`, and `--slot` stays PC only. A higher `--slot` takes effect only when the effect's `upcast` is true. The agent picks a monster's action as it picks any ability.
- **No new prompt.** Target and slot ride on the command. The only prompts around a cast are the existing ones: dice (`pc_dice = ask`) and reaction windows. A homebrew leveled spell cast as an action or bonus action opens a spell-cast window as an SRD cast does (ADR 0019). A homebrew cantrip opens none, and neither does a cast made as a reaction, which is ADR 0019's rule against counter-counters.
- **Cast card.** A new read-only `bench spell <spell-id> [--caster <id>] [--slot N]` prints the entry: level, casting time, concentration, save or attack kind, the caster's save DC or attack bonus and remaining slots, the effects resolved at that cast level (scaled dice, target count), and every agent clause and the upcast clause verbatim. It states how many target ids `bench action` takes, and the engine's refusal of a wrong count states the same number. It errors on an id no loaded file supplies and names the missing file. The agent shows the card before the user chooses target and slot.
- **Start-time checks.** `bench start` refuses a stat block when a homebrew cast sits in a section that doesn't match the entry's `casting_time` (`actions` is `action`, `bonus_actions` is `bonus_action`, `reactions` is `reaction`), when it sits in `traits`, `legendary_actions` or any other section, and when the entry's `casting_time` is `long`. The message names the action, its section and the casting time. It also refuses a leveled homebrew save or attack spell cast from a stat block with no `spellcasting` block, since the save DC and attack bonus come from that block and never from the entry. A utility spell needs no block. A stat block naming a homebrew id with no loaded file keeps the ADR 0005 rule, an `unmodeled_cast`, and `bench start` prints a warning that names the action and the missing id.
- **Spells are fixed at start.** `--spell` on any command against a live encounter is refused with a pointer to `bench start`.
- **Reaction-time spells.** A homebrew spell with `casting_time: reaction` has no trigger the engine reads, so no window offers it. The agent asks the user for a PC and decides for a monster, then runs it with `bench action` out of turn. This is ADR 0004's rule for reactions the engine doesn't model, so a PC's reaction is not routed through a prompt. Being a cast made as a reaction, it opens no spell-cast window either. A Counterspell-like homebrew spell is offered only as a `reactions` entry with the `spell_cast` trigger, as any reaction is.
- **Log.** The `cast` line names the spell and its cast level. A homebrew entry's agent clauses and `upcast_clause` come as `agent_clause` and `upcast_clause` events after the spell-cast window closes and before the saves, because the agent can't be expected to remember a user file. A countered cast emits none, since it never resolved, and logs `spell_countered` as in ADR 0019: the caster's action stays spent, the slot is not expended, and a per-day or innate usage is. A target's save logs as the existing `save` event, whose line gives the roll, the DC and the result, and a failed save is followed by the entry's effect events (damage, conditions, modifiers). Damage, concentration and attack rolls log as for SRD spells, and an attack-roll spell honors `pc_dice = ask`. No new event kinds. SRD spells keep the current rule: the agent reads `data/spells/effects.json`. The live-mode skill says which source to read for which spell.
- **Public view.** A monster's cast line and results show as for SRD spells. A monster's `agent_clause` events are hidden detail, and a PC's are shown. The agent narrates any unannounced effect when it takes hold.
- **Targets.** The target list follows the entry's effects as an SRD spell's does. A single-target spell takes its `target_count` ids, an area spell takes the creatures the agent names from the user's description, and a self spell takes none. Positions stay agent judgment.
- **Cast before an encounter.** A `long` homebrew spell is refused in live mode at `bench start`, as above. Whether batch can cast one before initiative stays on the map.
- **Left open.** Emitting agent clauses for SRD spells needs a replay-fingerprint change and goes on the map as a new question.
