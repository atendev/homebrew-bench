# Abilities run from a closed effect vocabulary, and an ability can be partly modeled

The engine runs an ability only from a fixed list of effects (attack, save, damage, condition, modifier, roll modifier, forced move, heal, teleport, move-then-attack, multiattack, use-action and cast, plus usage limits, reaction triggers and passive triggers). Anything outside the list stays as text. The engine never interprets prose.

An ability is modeled, partly modeled, inert, or unmodeled. A partly modeled ability has an `effects` list plus `agent_clauses`, text the agent resolves while the engine runs the rest. An inert ability has no combat effect (Amphibious, Spider Climb) and keeps its text. An unmodeled ability has no effects and only its text. This refines the all-or-nothing split in the monster schema.

SRD imports ship a default resolution for each unmodeled ability or clause, in three classes. Neutral defaults count as having no effect in the fight. Base-form defaults keep a shape-shifter in its stat block form. Skipped defaults (spawn and splitting, persistent zones, objects with their own HP) are skipped, and the report warns that they can change the numbers. Homebrew abilities never get a default. Batch refuses until each one has a resolution.

## Considered options

- Every ability is fully modeled or fully unmodeled. Rejected because a lycanthropy bite or Mummy Rotting Fist would block the whole attack for one long-term curse clause.
- A scripting layer so a stat block can define new effect types. Rejected for phase 1. The map already defers agent-written engine code, and a closed list keeps batch and live results comparable.
- Parse the `desc` prose into effects at run time. Rejected because it would make the engine's results depend on wording, and the engine could not tell the user why it read a sentence a certain way.

## Consequences

- A new effect type is an engine change, a schema change and a version bump. Adding one is the way to model a new pattern. Exception: an additive variant (`no_provoke`, ADR 0015; `disengage`, ticket 090) keeps version 1 while no loader checks `schema_version`. A second exception: ticket 060 renamed the `Lighting` value `normal` to `unspecified` and added `dim_light` under version 1, because no committed stat block used `normal` and `normal` stays a serde alias of `unspecified`, so old homebrew and state files still load.
- `disengage` (ticket 090, built in ticket 099) takes the Disengage step as part of an ability, usually a bonus action (Nimble Escape, Cunning Action, Deathless Agility, Hasten). It sets the same turn flag as `bench disengage`, so the creature's moves provoke no Opportunity Attack until its turn ends. It needs no target, and its log line names the ability: `goblin-warrior uses Nimble Escape to Disengage`. The other actions such abilities offer (Dash, Hide) stay agent clauses.
- Roll modifiers are trait effects read at roll time (ticket 049, built in ticket 060). The engine walks the roller's traits for `roll_modifier` effects whose `lighting` the encounter's one `settings.lighting` value meets and whose `target` matches the roll, and adds their disposition to that roll. The values are `unspecified` (the default, which meets no key), `dim_light`, `bright_light` and `sunlight`. Sunlight is Bright Light, so a modifier keyed to `bright_light` applies under `bright_light` or `sunlight`, while one keyed to `sunlight` or `dim_light` applies only under that value. A `roll_modifier` anywhere but the top level of a trait's effects, or keyed to `unspecified`, fails the stat block at load. Attack rolls and saving throws take the dispositions; ability checks carry them and change nothing, because the engine rolls no checks. Saves now take a disposition from every source through the same any-Advantage, any-Disadvantage rule as attacks, and draw a second d20 only when it is Advantage or Disadvantage. An event changed by a lighting modifier names the trait, as `(Disadvantage: Sunlight Sensitivity, sunlight)`.
- Reaction triggers (ticket 062, ADR 0018): a reaction entry may carry one modeled trigger field, `trigger: {hit_by_attack_roll: {attack: any | melee | ranged}}`, which opens a reaction window when the creature is hit. A `trigger` outside the reactions list fails at load. The duration `triggering_attack` ends once the attack that opened the window has resolved, and only an entry with a hit trigger may use it. The other reaction triggers (an attack roll made against the creature, taking damage or becoming Bloodied, a creature moving within N feet, a check or save) stay with agent judgment. Ticket 092 kept them there: a trigger is modeled only when an importable reaction needs it and it moves batch numbers, and only the spell-cast trigger, for Counterspell, passes that test. Its design is open in ticket 101. `schema_version` stays 1 by the `no_provoke` exception: both additions only add to the vocabulary.
- Timed modifiers have a bearer apart from their source (ticket 055, built in ticket 065). The bearer is the combatant whose stats or rolls the modifier changes; the source is the combatant whose ability made it, and concentration still ends what the source holds. `TimedModifier.bearer` is `target` (the default: each combatant the effect resolves against, so the one target under an `on_hit` or `on_failure`) or `self` (the creature using the ability: Shield, Parry). A top-level `target` modifier used with no target is refused. A `triggering_attack` modifier always lands on its reactor, because that duration exists only for the reactor's own hit reaction; this also keeps Parry right in stat block snapshots written before `bearer` existed. `ActiveModifier` gains `bearer`, `source_ability` and `ends_on_damage`, and none of the three serializes when absent or false, so saved states keep their tamper hashes. The engine always records `bearer`, so a modifier without one was saved before it existed: it is borne by its `source` and its Speed change stays inert, as it was then, so a resumed encounter plays as it did. Among modifiers on one bearer with the same `source_ability` and stat, only the most potent applies (the largest `add` magnitude, so -3 beats -1; for a `set` on Speed, the value farthest from the bearer's walk speed), else the most recent (PHB "Combining Spell Effects"); modifiers with no `source_ability` always apply. `ends_on_damage` removes the modifier when its bearer takes damage, as for conditions (Hypnotic Pattern's Speed 0). Speed modifiers are read by one walk-speed function shared by the engine, the batch policy and live mode: the lowest `set` wins; otherwise walk speed plus every `add`, doubled once per `double`, then halved once per `halve` (rounding down), never below 0; Grappled and Restrained give 0. `schema_version` stays 1 by the `no_provoke` exception: the fields are additive with defaults. A Fly Speed has no modifier form, so Fly is an agent clause.
- A modifier can grant an extra action and can act when it ends (ticket 055, built in ticket 066). The modifier target `extra_action: {only: [...]}`, with change `none`, gives its bearer one extra action on each of its turns, limited to the listed uses: `one_attack` (an action whose effects are exactly one Attack with one target, so no Multiattack, Cast or UseAction) and `disengage`; an empty list allows any action. Several applying `extra_action` modifiers still give one extra action, whose uses join. `ActionEconomy.extra_action_used` records it, and live mode spends it with `--extra` (ADR 0004). `TimedModifier.on_end` holds effects that resolve when that modifier instance ends, by duration, by its source's concentration ending, on damage or after its triggering attack, with the modifier's source as actor and its bearer as the one target; they don't fire when the encounter ends or when an override clears the modifier. Ending one of two Hastes on a bearer fires its lethargy even though the other still applies. The duration `until_end_of_next_turn` lasts until the end of the bearer's next turn and ignores a turn already under way; the engine turns it into `until_end_of_turn` when that turn starts, and `until_end_of_turn` ends when the bearer's current turn ends. Haste's fourth modifier is its extra action, and its `on_end` carries the lethargy (Incapacitated and a `set` 0 Speed, both `until_end_of_next_turn`), so the lethargy lands once. Dash, Hide and Utilize stay an agent clause. `schema_version` stays 1 by the `no_provoke` exception: `extra_action`, `on_end`, the two durations and `extra_action_used` are additive, and `on_end` and `extra_action_used` don't serialize when empty or false, so saved states keep their tamper hashes.
- A teleport names its subject (ticket 078). `Teleport.subject` is `self` (the default: the creature using the ability, as in Misty Step or "teleports up to 40 feet") or `target` (each target the effect resolves against). `target` is allowed where an effect may land on a target: at the top level of an ability used with targets, and under an attack's `on_hit` or a save's `on_failure`. A top-level `target` teleport used with no target is refused, as a top-level `target` modifier is. The subject's engagements are cleared on both sides and a `teleport` event is logged; range bands are unchanged. `subject` doesn't serialize when `self`, so older stat blocks, snapshots and command histories load and serialize unchanged.
- The SRD import fills the vocabulary from the structured fields where it can and from a hand-authored effects layer where the text carries the mechanic. The import review lists each mismatch.
- `recharge` usage accepts an optional `group` key (for example `breath_weapons` on the two breath actions of a metallic dragon). Abilities sharing a `group` on the same combatant share one recharge state and roll once at the start of the turn.
- Target design, built in tickets 036 to 039 (the first two bullets are built; the recharge and size items wait on tickets 038 and 039):
  - `MultiattackStep::Choice` carries options with per-option counts (`ChoiceOption { action_id, count }`) and a pick count; the engine resolves K distinct picks, taking the first K options until live mode (a pending prompt) and the batch tactics policy choose them. Swap-style multiattacks are a fixed `Action` step plus a `Choice`; `Multiattack.swap` is retired.
  - `Damage` carries an optional `if_target` condition gate, and the engine skips the entry unless the target has that condition (built in ticket 037). `if_target_from_actor` narrows the gate to a condition the damaging creature applied, which the engine already tracks through `ConditionInstance.source`; the Mimic's "Grappled by the mimic" bonus damage uses it. The gate stays inert in play until grapples are modeled: the engine only pushes a condition through `Effect::Condition`, the importer emits `"on_hit": []`, and the Mimic's Pseudopod grapple ("Large or smaller", escape DC 13) sits in an agent clause, so a modeled Bite deals the base 1d8 + 3 even against a grappled target. Modeling the grapple needs a size limit on `ConditionEffect` and an escape rule, because `Duration` has no way to end a grapple. Once ADR 0006's `bench override` exists (the CLI has no such command yet), the agent can record the grapple with `<target>.conditions` set to a `ConditionInstance` whose `source` is the mimic's combatant id, which turns the gate on. `Attack.on_hit` can carry `Effect::Damage`, but no SRD attack states plain unconditional later-clause damage, so the importer never emits it. The gate covers only target conditions. Damage that depends on the target being Bloodied, on Advantage, or on the attacker's movement stays an agent clause, as does recurring damage in a later sentence (start-of-turn damage, swallowed-creature acid, Hit Point maximum loss). An ability whose only damage is recurring is left unmodeled. The one later-sentence exception is an "Otherwise" sentence, which states the immediate damage after an HP gate (Incubus Nightmare, Sea Hag Death Glare, Solar Slaying Bow): the importer keeps that damage on the failed save and leaves the HP rule to the agent clause, which refers to "the modeled damage" instead of restating it, so the engine over-deals against targets at or under the gate. Effects stated in the Hit sentence after the damage (a condition, a Hit Point maximum loss) are not yet captured as clauses.
  - `recharge` dice accept `N-6` or a single `N` for N in 2 to 6; any other value is a load-time error. Recharge after rest maps to `per_rest` short with one use. Stat blocks may list `size_choice` alongside `size`.
- Multiattack steps can cast and branch (ticket 028). `MultiattackStep::Action` and `ChoiceOption` take an optional `cast` (a `Cast`): the slot is a use of the named Spellcasting action to cast that spell, so a dragon's "replace one attack with Spellcasting to cast Acid Arrow (level 3 version)" becomes a choice option with `slot_level: 3, upcast: true`. `MultiattackStep::Alternatives { sets }` runs exactly one set of steps; it holds "two Claw and one Snake Hair, or three Poison Ray" (Medusa, Barbed Devil), and an empty set marks a step the creature may skip (Erinyes's Entangling Rope, Dryad's Charm Monster). The engine takes the first set until live prompts and the batch tactics policy choose, so an optional step is always taken for now; importers put the non-empty set first. A cast slot must name an action the creature has. A cast resolves at its cast level, `slot_level` or the spell's own level, and the effects file's scaling rules apply per level above it (ADR 0014, ticket 059); `upcast` stays the importer's record of a "level N version" note and the engine ignores it. A Heal's `dice` is optional, so a flat heal such as the Heal spell's 70 rolls nothing, and `spellcasting_modifier: false` stops a cast from adding the caster's spellcasting ability modifier. A multiattack may name an action by its bare name without a trailing parenthetical. Variable counts have no step form: the Hydra's Bite count comes from a correction at its starting five heads, with an agent clause for heads lost or regrown. Damage of a type the creature chooses (Half-Dragon) stays an agent clause, and damage-type qualifiers that are conditional or chosen (Rakshasa, Half-Dragon) become `intake_flags` the agent applies.
- Spells are modeled through an engine-owned spell effects file keyed by SRD spell id, not through the stat block. A spell id absent from the file makes the cast an unmodeled ability with its default resolution. The future spells map can replace the file.
- Zones, spawned creatures and objects with their own HP stay unmodeled. If early reports show many monsters hitting the skipped class, revisit this ADR before adding engine entities.
