# Reference data is embedded in the binary and the release archive bundles the skill and NOTICE

The engine needs four committed datasets at runtime: graduated SRD fixtures (`data/fixtures/`), engine-owned spell effects (`data/spells/`), the 80 standard party stat blocks (`data/party/`), and the empirical baseline curve (`data/baseline/`). All four are embedded into the `bench` binary at compile time rather than unpacked as loose files under `~/.bench/data/`. Shipping a separate data directory was considered so users and agents could read raw JSON files on disk, but loose files can drift out of sync with the binary across updates, break baseline fingerprints, and add path-lookup failures when `bench` runs outside `~/.bench/`. The total dataset is small (a few megabytes of JSON), and read-only CLI commands (`bench fixture list`, `bench fixture show <id>`, `bench party show [--level <1-20>]`) expose the embedded JSON on stdout whenever the agent or user wants to inspect or copy a built-in stat block. Upstream `data/srd/2024/` and `data/srd/corrections.json` stay in the repo as import inputs only and are not embedded.

## Consequences

- `bench start` and `bench batch` accept either a file path on disk or a bare fixture slug resolved against embedded fixtures.
- Every per-platform release archive built by `cargo-dist` bundles `bench`, `NOTICE` (carrying the verbatim SRD 5.2.1 CC-BY-4.0 statement, modification note, and 5e-database MIT notice), `LICENSE`, and `.agents/skills/homebrew-bench/`.
- `install.sh` and `install.ps1` unpack `bin/bench`, `NOTICE`, `LICENSE`, and `skills/homebrew-bench/` into `~/.bench/` so the legal notice always travels with the binary.
- By default, the installer also writes plain copies of `homebrew-bench/` into `~/.agents/skills/homebrew-bench/` (covering Codex, Cursor, Gemini CLI, Antigravity CLI, Copilot, Windsurf/Devin, opencode, Amp, Roo Code, Goose, Junie, and Zed) and into `~/.claude/skills/`, `~/.cline/skills/`, and `~/.kiro/skills/` when their binary is on `PATH` or their `~/.<agent>` directory exists, with `--no-skills` and `--agent <name|all>` to override.
- Inside the repository, `.agents/skills/homebrew-bench/` is the canonical skill directory (`SKILL.md` with only `name` and `description` frontmatter, plus optional `references/`), `.claude/skills/homebrew-bench` is a committed relative symlink, and root `AGENTS.md` points to `.agents/skills/homebrew-bench/SKILL.md`.
