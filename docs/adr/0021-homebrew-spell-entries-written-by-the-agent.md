# Homebrew spell entries are written by the agent into their own file and reviewed by the user

A pasted homebrew spell has to become a spell entry before batch or live mode can cast it. Ticket 002 of the spell-testing map ([Homebrew spell intake rules](../../.plan/closed/002-homebrew-spell-intake-rules.md)) chose who writes the entry, where it lives, what intake flags or refuses, and how the user reviews it. It follows monster intake (batch mode steps 1 and 2) wherever spells allow.

## Considered options

- **Append homebrew entries to `data/spells/effects.json`.** Rejected. That file is engine-owned, keyed by SRD id and embedded in the binary (ADR 0014). User content stays out of it.
- **Embed the entry in the stat block or party file that casts it.** Rejected. One spell would need copies on the monster side, the party side and in batch.
- **Scaffold the entry by script, as SRD entries are.** Rejected. A homebrew spell has no structured SRD fields to scaffold from.
- **The agent writes the whole entry, and the user reviews it.** Adopted. ADR 0014 rejected agent-written entries for SRD spells because they would churn against upstream SRD text. A homebrew entry is written once per paste and has no upstream, so that reason does not apply.

## Consequences

- **File.** Each homebrew spell is its own file, `./.bench/spells/<id>.json` by convention, with the effects-file entry schema plus `source: "homebrew"` and the user's text verbatim in `pasted_source`. `bench` reads it only from a repeatable `--spell <file>` flag on every command that can cast. Two loaded files with one id are an error. A live encounter copies the entry into its state at creation, so replay and the tamper check (ADR 0007) don't depend on the file.
- **Ids.** A homebrew id equal to an SRD id is refused, and the agent picks a distinct kebab-case id. Shadowing would silently change SRD comparison rows and SRD casts in fixtures. A stat block naming an id no loaded file supplies keeps the ADR 0005 rule: the cast is an unmodeled ability. `bench schema validate` warns and names the id.
- **Cast time.** Spell entries gain `casting_time`: `action`, `bonus_action`, `reaction` or `long` (1 minute or more). Homebrew entries require it. SRD entries get it from SRD data, checked by `check-spell-effects.py`. The batch swap (ADR 0020) puts the cast on the matching slot. `long` marks a spell castable only before an encounter, and batch reads it "not measured". A reaction trigger outside the reaction-trigger vocabulary is an agent clause.
- **Caster numbers.** An entry uses the caster's save DC and attack bonus, as SRD entries do. A fixed number in the text gets an intake flag and is left out. If the user keeps it at review, it becomes an agent clause, never an engine value. Spell lift shares one DC across all spells (ADR 0020).
- **Intake flags.** Each flag has a `path` and a `note`, as on monsters, and none block. Intake flags cover a value inferred rather than read (save ability, damage type, duration, target count, level, concentration, cast time), wording with no standard rules reading, and numbers off the level's norms: damage outside the DMG spell damage guideline (the note names the guideline), a cantrip with no damage growth, an upcast with no clear per-level amount. A bonus action or reaction cast time is flagged too, since the batch tactics policy may not cast the spell as written. An inferred level is flagged, and the review needs the user to confirm it.
- **Refusals.** Intake writes no entry for a spell with no effect in the vocabulary, a spell with no combat effect, a spell whose level the text doesn't give and the user doesn't confirm, or an id collision. The no-combat-effect refusal says live mode can still play the spell as agent judgment. This settles the question ADR 0020 left open: intake refuses such a spell, and "not measured" remains only for an accepted spell that batch can't cast in a fight, such as a `long` cast. A partly modeled spell is accepted. Each sentence outside the vocabulary becomes a verbatim agent clause, shown at review, never dropped.
- **Review.** The agent shows a table of every field with its value and whether it was read or inferred, every agent clause verbatim, and every intake flag. The user confirms, corrects in chat, or edits the file. Each change is revalidated and the table shown again until the user confirms. There is no approval field in the file: the gate is the skill step, as in monster intake.
- **No defaults.** A homebrew entry never carries a default resolution (ADR 0005). Its agent clauses and upcast clause are resolved per run through the assumptions file, and batch refuses until each is resolved. The build picks the assumption path that names a spell's clauses.
- **Fingerprints.** A batch report records a fingerprint of each homebrew entry it ran, as the spell baseline does, so reports from different versions of a file can be told apart. A live encounter fingerprints the copy in its state.
