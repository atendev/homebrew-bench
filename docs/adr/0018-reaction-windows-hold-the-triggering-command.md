# Reaction windows hold the triggering command

ADR 0004 says live mode pauses on a pending prompt when a reaction changes an action already in progress, but no prompt existed. The agent named Opportunity Attack reactors before the move (ADR 0015) and cast Shield with `bench action` after the hit, when the damage had already landed. No stat-block reaction carried a trigger the engine could read, and the old `ReactionTrigger` enum was never used. Ticket 047 decided the design and ticket 062 built it.

- **Two triggers.** A creature leaving the reactor's reach opens an Opportunity Attack window, which every creature has. Being hit by an attack roll opens a window for a reaction entry with `trigger: {hit_by_attack_roll: {attack: any | melee | ranged}}`. A melee attack is one with no range. `trigger` may appear only on a reaction, and the loader refuses it anywhere else. The other ADR 0005 triggers stay agent judgment.
- **One window per reactor.** An Opportunity Attack window goes to each reactor that passes ADR 0015's eligibility rule, isn't named in `--opportunity` and hasn't declined. It offers the reactor's default attack first, then every other ready single melee attack. A move asks all its windows in initiative order before any attack resolves. A hit window goes to the creature hit. It needs the shared checks (can act, no "no Reactions" modifier, reaction unspent) and a reaction whose filter matches the attack and whose usage and spell slot are ready. A critical hit still opens it.
- **The held request runs again.** A window with no answer stops the run. The engine discards the trial copy and saves a `reaction` pending prompt holding the request, the dice faces so far, `engine_fills_rest`, the hit-window answers so far and the options. `bench respond --take [<id>]` or `--decline` answers it. A taken Opportunity Attack joins the move's `opportunity` list and a declined one joins its `declined` list. A hit answer joins the queued answers. Then the request runs again from the state before the command, so the dice come up the same. Dice prompts and reaction windows inside one request are asked in the order the engine meets them.
- **Resolving a taken hit reaction.** It runs right after the hit is known and before damage, through the normal reaction path, with the attacker as its target. That spends the reaction, the usage and any slot. Then the engine checks the hit again against the new AC, and a natural 20 still hits. The duration `triggering_attack` ends once that attack resolves, so Parry's AC applies to one attack only. Only an entry with a hit trigger may use it.
- **The decider seam.** The engine asks a reaction decider on the state about each window. The decider is never stored and stays out of `game_hash`. Live mode's decider reads queued answers and waits when none is left. Batch's decider passes every window, so batch logs keep the `opportunity_attack` notice. A decider's answer may carry a one-line reason, which the engine logs as a `reaction_reason` event; live mode and the pass-all decider give none. Since ticket 063, batch installs the tactics policy as its decider instead (policy v3, ADR 0012), and every batch window it decides logs a reason, taken or held.
- **The gate.** Windows open only when `settings.reaction_windows` is true. `bench start` sets it, and since ticket 063 so do batch encounters, which are never refolded from a history. Live encounters saved before engine 0.1.5 leave it false and behave as before. `undo` and `replay` refold the whole history through a path that ignores pending prompts, so without the gate an old move that left reach would stop at a new window, the next command would clear the prompt, and the move would vanish without an error.
- **No legendary prompt.** Legendary actions stay declared on the end-turn (ADR 0016). A legendary action doesn't change an action in progress, and a prompt would hold every end-turn in a legendary encounter.
- **Log and public view.** `PROMPT <message>` opens a window, then `PROMPT <message> answered: takes <name>` or `PROMPT <message> declined`, then `REACTION <reactor>: <name> (hit by <attacker>)` before the reaction's own lines, an `attack_rechecked` line, and an `agent_clause` line for each of the reaction's agent clauses. Opportunity Attacks keep `OPPORTUNITY ATTACK <reactor> on <mover> (reaction)`. A reactor that declined an Opportunity Attack window in live mode gets no `opportunity_attack` notice. The public view hides a monster's window while it is open and after a decline, shows the answer line when the monster takes it, and shows every PC window.

## Considered options

- **A suspended engine state in the middle of an action.** Rejected. It would need every effect resolver to resume partway, and undo and replay already work for held requests.
- **One Opportunity Attack prompt listing every reactor.** Rejected. CONTEXT.md defines a window as an offer to one combatant, and one prompt would mix a PC's decision (the user's) with a monster's (the agent's).
- **An up-front decline flag on `bench move`.** Left out. An unwanted window costs one `bench respond --decline`, and a flag can come later without changing the contract.
- **Opening all six ADR 0005 triggers.** Rejected. No modeled ability uses the other four, and "moves within N feet" needs positions.

## Consequences

- Parry (7 SRD fixtures) and the pirate captain's Riposte import as a hit trigger with a `triggering_attack` AC modifier. Riposte's extra attack stays an agent clause, and holding a weapon is assumed. The party generator writes the trigger on Shield. The mummy lord's Whirlwind of Sand stays skipped. The stone giant's Deflect Missile gets no trigger and stays mis-modeled: its damage reduction is dropped and its save fires without the trigger.
- `bench action` off-turn still runs a reaction, for triggers the engine doesn't open windows for, such as Shield against Magic Missile.
- Batch numbers don't change. The fixture-set and party fingerprints do, so the curve reads stale until ticket 056 regenerates it.
- `schema_version` stays 1. `trigger` and `triggering_attack` only add to the vocabulary, and every stat block that loaded before still loads, by the exception ADR 0015 recorded.
- The engine version moves to 0.1.5 because a live encounter started on it can replay into prompts an older engine never opened.
