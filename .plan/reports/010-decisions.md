# Ticket 010 decisions

1. **Which ticket.** The frontier held 010, 011, 014, 012 and 015. I took 010 (Skill: homebrew spell intake and live casting), the first listed. Main thread.
2. **Where intake lives.** The ticket asked for a new reference beside `batch-mode.md`. Choice: `references/spell-intake.md` with four steps (refuse or accept, write the entry, flag, validate and review), each ending on a completion check, in the same shape as batch mode's steps. `SKILL.md` links it under "Pick the mode". Main thread. Auditor: no objection.
3. **Skill description.** Options: leave the description on monsters only, or add a spell branch. Choice: the description now names monsters and spells and adds one trigger, "pastes a homebrew spell to cast in a fight (spell intake)". Without it, a pasted spell would not load the skill. The vocabulary line gains spell entry, intake flag and cast card. Main thread.
4. **Where intake flags go.** ADR 0021 gives each flag a `path` and a `note`, but a spell entry has no `intake_flags` field and `bench` refuses unknown keys (checked by running the binary). Options: keep flags only in the review table, add an engine field, or write them into the existing `notes` string. Choice: `notes`, one `<path>: <note>` per line, so the flags stay in the file without an engine change. A two-line `notes` file passes `bench spell --spell`. Main thread. Auditor round 1 asked for the field's shape, and the text now says "a single string". Possible follow-up for the map: an `intake_flags` field on spell entries.
5. **How the agent validates an entry.** `bench schema validate` takes a stat block, not a spell file. Choice: `bench spell <id> --spell <file>`, which parses the file through the loader, refuses an SRD id or unknown key, and prints the cast card the review table uses. Main thread.
6. **SRD id refusal.** ADR 0021 says the agent picks a distinct id and lists an id clash as a refusal. Choice: the agent checks its id with `bench spell <id>` (`not_found` means free) and proposes another when the name gives an SRD id. It refuses only when the user keeps the SRD id. Main thread.
7. **Refusal wording.** The ticket asked for messages for the four cases, and the decisions gave none. I wrote one sentence each. Only the no-combat-effect message mentions live mode, as ADR 0021 says. The no-level case first asks the user, a step the auditor asked for in round 1. Main thread, auditor.
8. **DMG damage norms.** The damage flag needs the DMG Spell Damage table, which the agent can't look up from the skill. Choice: inline the ten-row table with its source (Dungeon Master's Guide, Creating a Spell) and the 25 percent allowance for no damage on a success. The auditor checked it against DMG p.63. Main thread.
9. **Cantrip growth.** The engine multiplies cantrip damage dice at caster levels 5, 11 and 17 whatever the entry says (`engine.rs` `cast_context`). The flag for a cantrip with no growth says so, and a cantrip that grows some other way keeps its growth sentence as an agent clause. Main thread.
10. **Live set-up step.** A new step 2 in live mode adds the cast action: the `cast` effect shape, the section matching `casting_time`, `upcast` for PCs, a fixed `slot_level` for monsters, the `spellcasting` block, the two reaction triggers the engine reads, and `bench schema validate <stat block> --spell <file>`. The agent shows each action before `bench start`. The auditor questioned the validate syntax and the trigger shapes in round 1. Both were already checked against `bench help --json`, `bench schema monster` and the SRD mage fixture. Main thread.
11. **Start step.** It passes `--spell` once per spell and lists what `bench start` refuses. A missing id leaves `unmodeled_cast` events, and the agent runs intake for it, then starts again. Round 1 asked for that last sentence. Main thread, auditor.
12. **Cast card before a cast.** A new bullet in Run turns shows `bench spell <id> --caster <actor> [--slot N]` before the user picks targets and slot. With `--caster` the card reads the encounter's copy, so it takes no `--spell`. Round 1 asked for that clarification, and a live run confirmed it. Main thread, auditor.
13. **Clause source.** The old line said the engine logs no clauses on cast. It now says the log prints `agent_clause` events for a homebrew spell and none on a countered cast, and that an SRD spell's clauses are in `data/spells/effects.json` or on its cast card. The card covers users outside a repo checkout, where the file isn't at hand. Main thread.
14. **Reaction spells and the public view.** A homebrew reaction spell with no engine trigger is cast out of turn with `bench action` and opens no spell-cast window. "Showing players" now says the public view hides a monster's clause events. Main thread.
15. **Checks.** A scratch live run started an encounter with `--spell`, printed the caster's card at slot 3, saw a 0-target cast refused with the card's sentence, and logged `cast`, `agent_clause`, `save` and `damage` in that order. The install tests pass (10 passed). No engine code changed, so no version bump. Main thread.
16. **Audit.** One haiku auditor. Round 1 raised seven items: four were fixed (no-level ask, the `unmodeled_cast` bullet, the missing-file step, the `notes` shape), and three were answered with evidence from the binary (card reads the encounter, `schema validate --spell`, trigger shapes). In round 2 the auditor first read a stale diff file, because I had not regenerated it. After I regenerated it, the auditor checked the five changed hunks and returned APPROVE.
17. **Skipped gates.** No requirements or implementation confirmation was asked, per the runner's override. The audit named `pocock /to-spec` and `pstack /architect`; I used the ticket's skills (`writing-for-agents`, `domain-modeling` terms, and a haiku auditor in place of `code-review`) instead, since this ticket writes skill docs and no spec or code. The Jev audit halted once on a model mismatch, and the user switched to Opus and replied "proceed". `AGENTS.md` and `.cargo/` are the user's changes and stay out of the commit.
