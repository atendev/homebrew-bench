# Ticket 008 decisions

1. **Which ticket.** The frontier held 008, 009, 011, 012, 014 and 015. I took 008, the first listed. Main thread. Audit: not in scope for the auditor.
2. **Where agent clauses are emitted.** Options: emit them right after the spell-cast window closes and before the slot is spent, or emit them just before the existing `upcast_clause` event. Choice: just before `upcast_clause`, inside `cast_spell` and after the counter check. A countered cast returns early, so it emits none. Moving the existing `upcast_clause` earlier would reorder SRD logs, so it stays put. Main thread. Auditor confirmed the insertion point.
3. **Homebrew only.** Clauses are emitted only when `spell.is_homebrew()`. SRD clauses stay with the agent, which is the open fog item on the map. SRD logs are unchanged. Main thread. Auditor confirmed.
4. **No new event kinds.** The clause events reuse `agent_clause`, with the message `<actor> <spell>, agent clause: <text>`, the same shape the reaction clauses already use. Main thread.
5. **Public view.** Options: hide monster clause events only for homebrew casts, or hide every monster `agent_clause` and `upcast_clause`. Choice: hide every one, as the ticket states the rule without a homebrew limit. This also hides a monster's reaction clauses (Riposte, Protective Magic) and an SRD monster's `upcast_clause` in the public view. The private log is unchanged. The changelog says so. Main thread. The auditor raised this as undisclosed, then accepted it once the changelog named it.
6. **`pc_dice = ask`.** No code change. The homebrew attack path already shares the SRD dice path, so a test now pins it. Main thread.
7. **Version.** Engine 0.1.39 in `Cargo.toml`, `Cargo.lock` and the curve's `engine_version`, plus a changelog entry. Batch numbers are unchanged, as the calibration tests confirm. Main thread.
