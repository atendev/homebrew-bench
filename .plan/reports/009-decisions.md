# Ticket 009 decisions

1. **Which ticket.** The frontier held 009, 011, 014, 012 and 015. I took 009 (Cast card), the first listed. Main thread. Audit: not in scope for the auditor.
2. **Where the code lives.** Options: add the card to `engine.rs` (7,700 lines), to `spell.rs`, or to a new `bench-core/src/cast_card.rs`. Choice: a new module that holds `TargetCount`, the card, and the live target check. The engine gains two small public functions, `cast_effects` and `check_homebrew_upcast`, and makes `cast_level` public. Main thread. Auditor: no objection.
3. **One scaling path.** `engine::cast_effects` scales a spell and binds the caster's numbers. `cast_spell`, `bound_cast_effects` (batch tactics) and the card all call it, so the card can't drift from the cast. This moved binding ahead of the spell-cast window in `cast_spell`. Binding reads only the stat block, so the order change has no effect, and the regenerated curve differs only in its engine version. Main thread. Auditor confirmed the refactor changes no behavior.
4. **The target count rule.** The engine refused no target count before this ticket. It took the first `target_count` ids for an attack or capped area and every id for anything else. Choice: `TargetCount::of(effects)` reads that same rule. An attack or capped area takes 1 to its cap. Saves, damage, conditions, heals, forced moves, counters and target-borne modifiers or teleports take 1 or more. Temporary HP takes any number, since none means the caster. A self-only spell takes none. Its `Display` is the sentence the card prints and the refusal quotes. Main thread. Auditor confirmed that both share one function.
5. **Where the refusal sits.** Options: in `resolve_action`, which batch shares, or in live `apply` before the engine runs. Choice: live only, since batch tactics already pass counts the engine accepts and a refusal there could change batch numbers silently. The message reads `fire-bolt casts fire-bolt at level 0, which takes 1 target id; 2 given`. Main thread. Auditor confirmed that batch is untouched.
6. **Self spells refuse a target id.** ADR 0022 says a self spell takes none, so `bench action <pc> shield <attacker>` is now refused. The live-mode guide told the agent to pass a target for out-of-turn reactions, so one sentence there now points at `bench spell` for a spell's count. The rest of the skill is ticket 010. Main thread.
7. **Single-target save spells read "1 or more".** A save effect has no `target_count`, so a single-target save spell takes every id passed. This is the map's fog on target caps for non-attack spells. The card states what the engine does today and leaves the cap to that fog. The auditor raised it in round 1 and accepted it as a known gap.
8. **Which book the card reads.** With `--caster` or `-e`, the card reads the running encounter's book and the caster's numbers, and refuses `--spell` with the existing pointer to `bench start`. Without either, it reads the SRD plus repeatable `--spell` files. An unknown id is `not_found`, naming `data/spells/effects.json` and the `--spell` files read, or the encounter's homebrew spells. A missing `--spell` file is `invalid_argument` from the loader, which names the file. Main thread.
9. **Default cast level.** With a caster and no `--slot`, the card uses the slot level of the caster's first action that casts the spell, else the spell's own level. A monster with `--slot` is refused with the engine's wording. Main thread.
10. **Homebrew upcast flag.** Round 1 found that the card printed an upcast that `bench action --slot` refuses when the cast has `upcast: false`. Fix: `check_homebrew_upcast` is now shared. With a caster and an explicit `--slot`, the card refuses when every action that casts the spell would be refused. Without a caster, a homebrew card above its level carries a note. Round 2 asked for the same check on the default slot path. I declined, because `resolve_action` runs the check only when `--slot` is given, so a stat block cast declared above a homebrew level with `upcast: false` runs scaled. The card matches that. The auditor verified this and approved. Possible follow-up for the map: `bench start` doesn't refuse such a declaration.
11. **Output.** The card is JSON in the usual envelope, with fields for level, cast level, casting time, concentration, rolls, bound effects, target count, clauses, upcast flag, caster numbers (save DC, attack bonus, slots left, casting actions) and notes, plus a `text` rendering for the agent to show. Effects render as one-line JSON in `text`. Notes say when DC, bonus or cantrip dice need `--caster`. `bench help --json` lists `spell` because the catalog comes from clap. Main thread.
12. **Version.** Engine 0.1.40 in `Cargo.toml`, `Cargo.lock` and the curve's `engine_version`, plus a changelog entry. I regenerated the curve with `--threads 4`, and only the engine version changed. Main thread.
13. **Tests.** Card: a homebrew save spell at its level and upcast (3d6, then 5d6 at level 4), a slot below the spell's level, a cantrip at caster level 5 (2d10, +7) and bare (1d10 with the note), caster numbers and spent slots, a monster refused `--slot`, the upcast flag with and without a caster, and target-count sentences. Live: a wrong count is refused with the card's sentence, for 2 ids and 0 ids. CLI: a card from a `--spell` file at `--slot 3`, an unknown id, a missing file, a caster card from an encounter, `--spell` refused against an encounter, a homebrew id unknown to the encounter, and `spell` in `help --json`. All 532 core and 29 CLI tests pass, along with every other suite. Clippy shows only the two warnings master already has. Main thread.
14. **Audit.** One haiku auditor. Round 1 raised three items: the upcast flag (fixed), a supposed borrow of a temporary (no such problem, since `SpellBook::srd()` is `'static` and the tests compile), and single-target saves (fog, accepted). Round 2 raised the default slot path (rebutted with the engine's code). Round 3: APPROVE.
15. **Skipped gates.** No requirements or implementation confirmation was asked, per the runner's override. No remote CI runs on a branch push, since the only workflow is the tag-triggered `release.yml`, so step 6 is skipped. The thread was renamed to the ticket name. The Jev audit halted once on a model mismatch and ran on after the user switched to Opus and replied "proceed". `AGENTS.md` and `.cargo/` are the user's changes and stay out of the commit.
