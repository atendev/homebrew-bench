# Ticket 034 implementation report

Ticket: `.plan/tickets/034-release-packaging-legal-notices-and-installers.md`. Requirements: `.plan/reports/034-requirements.md`. Diff reviewed: `/tmp/ticket-034.diff`, which excludes the cargo-dist generated `.github/workflows/release.yml`.

## What was built

- `NOTICE`: the SRD 5.2.1 CC-BY-4.0 statement with the dndbeyond and creativecommons URLs, a modification note, and the 5e-database MIT notice copied verbatim from `data/srd/LICENSE-5e-database.md`. It names no other Wizards attribution.
- `LICENSE`: MIT for the repository code, copyright "Nathan Beene" 2026, with a line pointing to NOTICE for the embedded SRD and 5e-database content.
- `README.md`: what bench does, install from the release or a clone, an options table, updating, sample batch and live prompts, repository layout, and a license summary.
- `Cargo.toml`: `[workspace.metadata.dist]` for cargo-dist 0.34.0 with five targets, `.tar.gz` and `.zip` archives, sha256 checksums, `include` of NOTICE, LICENSE and `.agents/skills/homebrew-bench`, `installers = []`, and `pr-run-mode = "plan"`. Also a `[profile.dist]` that inherits release with thin LTO.
- `.github/workflows/release.yml`: generated by dist 0.34.0. It runs `dist plan` on pull requests and builds release archives on tags.
- `install.sh`: POSIX sh. Flags `--no-skills`, `--agent` (repeatable, or `all`), `--version` (default latest), `--from-source`, `--help`. Detects OS and arch, downloads `bench-<triple>.tar.gz`, checks its `.sha256` when present, and copies `bin/bench`, NOTICE, LICENSE and `skills/homebrew-bench` into `~/.bench`. Creates `config.toml` and `index` only when missing. Copies the skill to `~/.agents/skills` by default, plus `~/.claude`, `~/.cline` and `~/.kiro` when detected. Inside a checkout with no `--version`, it builds the checkout. When no archive fits, it clones the requested tag (or the default branch) and builds it. Test overrides: `BENCH_HOME`, `BENCH_REPO`, `BENCH_RELEASES_URL`, `BENCH_GIT_URL`, `BENCH_TARGET`.
- `install.ps1`: PowerShell mirror of `install.sh` with the same flags (`--no-skills` spelling), a `.zip` archive, copies instead of symlinks, the checksum check, `%USERPROFILE%\.bench`, and the Windows skill folders.
- `update.sh`: runs the local `install.sh` when it sits beside it, otherwise downloads `install.sh` from main and runs it. All arguments pass through.
- `bench/tests/install.rs`: Unix-only integration tests. Each test uses a temp HOME, a stub PATH, a `file://` release server built from tar archives, and a fake cargo. Ten tests run by default, plus one ignored test that runs real cargo.
- `CHANGELOG.md`: Unreleased entries for the installers, the release archives and the legal files.

## Deviations from the ticket

- License type: the ticket names no type. MIT was chosen by the user.
- NOTICE modification note: the two sentences "applied corrections to upstream data faults" and "to build the CR baseline curve" come from the implementation. The requirements report does not source them. Check them before release.
- Clone builds: run from a clone with no `--version`, `install.sh` and `install.ps1` build the checkout. The ticket says download unless `--from-source` or no archive exists. This is the user's choice on O6 and changes what a clone install does.
- Windows copy fallback for `.claude/skills/homebrew-bench`: dropped (O5). The installer writes only user-level copies, taken from `.agents/skills/homebrew-bench`.
- `installers = []` disables dist's own shell and PowerShell installers. The ticket does not mention this.
- `.tar.gz` is set in the config. The cargo-dist default is `.tar.xz`, which the requirements assumed.
- `[profile.dist]` with thin LTO was added. It is not in the ticket or the requirements, and the diff does not record why.
- Checksums are verified when a `.sha256` file exists (O12).
- An explicit `--agent` replaces detection (O4).
- No `update.ps1` (O9). Re-running `install.ps1` is the Windows update path.
- Config defaults: the installer writes its own template. A test checks it equals `Config::default()`. The requirements suggested one shared source (O13).
- A missing release is built from a clone of its tag instead of failing. This was an audit round 1 fix.

## Verification

- `cargo test --workspace` is green.
- `bench/tests/install.rs`: 10 tests pass on Linux. They cover flag parsing and exit codes, release layout, a named tag, the checksum mismatch, skill target detection with fake `claude` and `kiro`, `--agent all`, `--no-skills`, re-run preserving user files, the from-source layout, a checkout build, a missing release cloned from git, a piped install inside a clone, and `update.sh`. The ignored `from_source_with_real_cargo` test was run and passed.
- The tests are `#![cfg(unix)]`, so `cargo test` on Windows runs none of them.
- cargo-dist 0.34.0 (in `target/tools`): `dist plan` lists `bench-<triple>.tar.gz` and `.zip` for all five targets. Each archive holds `bench`, LICENSE, NOTICE and `homebrew-bench`. dist places the skill under `homebrew-bench/`, not `.agents/skills/homebrew-bench/`. The installers find `SKILL.md` by search, so either layout works.
- A real Linux archive from `dist build` was installed with `install.sh`. The checksum check passed and `bench help --json` ran.
- `install.ps1` was reviewed by reading only. This is the deferred audit round 1 item. `pwsh` is not installed, so the script has never run.
- Audit round 1 raised 8 points. Five were fixed: usage errors exit 2 with usage text; a missing release clones and builds the requested release, with a `BENCH_GIT_URL` override; git clone failures are checked; piped runs never treat the cwd as a checkout; one test assertion was vacuous. One was deferred and is recorded here.
- Audit round 2: APPROVE. Its non-blocking note still applies. When neither `sha256sum` nor `shasum` exists, `install.sh` skips checksum verification silently. The diff shows this unchanged.
