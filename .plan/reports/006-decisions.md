# Ticket 006 decisions

1. **Which ticket.** The frontier held 006, 012, 014 and 015. I took 006, the first listed. Main thread.
2. **Book shape.** Options: keep a global `catalog()` and add an override argument, a thread-local, or an explicit value. Choice: `SpellBook<'a>`, a value holding the SRD map and a slice of homebrew entries, with `get` checking homebrew first. Callers pass it, so no hidden state. Main thread. Auditor: sound.
3. **Where homebrew lives.** `EncounterState.homebrew_spells`, serde default and skipped when empty, so old saves load with none and their hashes don't change. Main thread. The auditor found a shadowing hole on state load, since plain serde skips the loader's checks. Fix: a `checked_homebrew` deserializer that refuses an SRD id, a repeated id and a non-homebrew entry. Main thread, on the auditor's finding.
4. **Loader.** `load_homebrew(paths)` reuses `SpellEffect::parse`, so `pasted_source` is enforced as ticket 005 deferred. It also refuses a file whose `source` is not `homebrew`, which the ticket did not list. Each message names the file and the id. Main thread.
5. **Callers without a state.** `bound_cast_effects`, `missing_spells` and `unapplied_upcasts` take a `&SpellBook`. Tactics holds one on `Ctx` and passes it to its free helpers. Batch and baseline use an SRD-only book until tickets 011 and 007 give them homebrew. Main thread.
6. **The stat block check.** Its deserialize-time cast-level check has no encounter to read, so it uses an SRD-only book. A new public `check_block_casts` runs the same rule against a book that holds loaded homebrew, and `bench schema validate --spell` calls it. A below-level homebrew cast therefore fails validation instead of at parse time. Main thread.
7. **Validate warning.** A cast naming an id that neither the SRD nor a `--spell` file supplies adds a warning that names the id. A bad `--spell` file fails with `invalid_argument`. Main thread.
8. **Error paths.** The embedded SRD file cannot fail to load in practice. Where it did, the engine kept its `unmodeled_cast` log, `ability_ready` fails only cast abilities as before, and tactics falls back to a homebrew-only book (`SpellBook::homebrew_only`). Main thread. The auditor flagged the three policies as uneven. I kept the old behaviour of each site rather than unify them.
9. **Version.** Engine 0.1.37, changelog entry, and the curve's `engine_version` edited by hand. Batch numbers are unchanged, as the calibration test confirms. Main thread.
10. **Tests.** Added: homebrew-first lookup and SRD fallback; precedence over an SRD id; a loaded file joins the book; id clash and duplicate refused naming file and id; a non-homebrew file refused; a saved list held to the loader rules; a state cast resolves a homebrew spell and a missing id stays unmodeled; a state with none serializes without the key and round-trips byte-identical; a CLI test for `schema validate --spell`. 504 core and 27 CLI tests pass. Clippy shows only two warnings that master also has.
11. **Audit.** One haiku auditor. Round 1 raised six items: one real (item 3 above), test gaps, two uneven fallbacks, formatting and two notes. Round 2: APPROVE. The auditor accepted the uneven fallbacks and noted that `SpellBook::new` itself takes any list, so the clash rule holds at the loader and at state load.
12. **Skipped gates.** No requirements or implementation confirmation was asked, per the runner's override. The thread rename was not tried.
