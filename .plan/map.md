# Map: homebrew-bench

## Destination

A repo someone downloads to test D&D 5e homebrew monsters by running combats and reading the numbers, aimed at DMs first and homebrew designers second. One engine holds combat state and does the rules math. An agent-agnostic skill teaches any LLM how to use it, in two modes:

- Batch mode: the agent converts pasted monster text to a structured form, flags ambiguous wording, runs many fights, and writes a report with win rate, rounds, and damage per round across party levels, compared with CR guidance.
- Live mode: the agent DMs one full combat encounter turn by turn through the engine while the user controls the party.

Both modes ship in phase 1. Everything the engine can't model is labeled agent judgment. Every engine action goes into a human-readable log.

- [Build batch reactions policy](closed/063-build-batch-reactions-policy.md): batch opens reaction windows and the policy (now v3) decides each one: Shield or Parry only when it turns the hit into a miss, an Opportunity Attack only above the reaction reserve (`AC_POINT_VALUE` 0.1), and the step-out penalty counts only those attacks. Each window logs a reason, the engine stays 0.1.5, the curve reads stale on the policy until 056 regenerates it, and wins and losses held on goblin, knight and adult red dragon while DPR fell where Shield and Parry fired.
- [Build modifier bearers and Speed modifiers](closed/065-build-modifier-bearers-and-speed-modifiers.md): timed modifiers land on their target unless marked `"bearer": "self"` (Shield, Parry, Riposte), and a `triggering_attack` modifier always lands on its reactor so old Parry snapshots stay right. `EncounterState::modifiers_on` applies one spell's modifiers once per bearer (most potent, else most recent), `ends_on_damage` ends Hypnotic Pattern's Speed 0, and `engine::walk_speed` serves the engine, policy and live default move, while declared `--feet` stays trusted for Dash. Fly is an agent clause, the engine is 0.1.6, 0.1.5 states load with each bearer read as its source, and batch numbers are unchanged on goblin, ogre, adult red dragon and knight.

## Not yet specified

- Bonus-action Disengage. Nimble Escape (8 fixtures, goblins among them) and Cunning Action import as unmodeled and skipped. Under policy v3 those creatures pay Opportunity Attacks they would avoid at a table, so they read a little weaker. Open: whether Nimble Escape imports as a bonus action that runs the Disengage step, and when the policy should spend it ([Batch policy takes reactions](closed/046-batch-policy-takes-reactions.md)).
- Darkness and Darkvision. An encounter-wide `darkness` lighting value, read against each creature's Darkvision, Blindsight and Truesight, would need no positions: a creature that can't see in it is Blinded. Sense range doesn't count: ADR 0017 treats every sense as reaching every band. Open: how the standard party sees (it has no Darkvision and carries no light), how a homebrew "Dim Light or Darkness" trait maps, and whether the batch report needs a second run in darkness ([Encounter lighting setting](closed/049-encounter-lighting-setting.md)).
- Reaction triggers beyond leaving reach and being hit by an attack roll. ADR 0005 lists four more: an attack roll made against the creature, taking damage or becoming Bloodied, a creature moving within N feet, and a creature making a check or save. There is also the dormant spell-cast trigger. Nothing modeled uses them yet, so the agent handles them. The open questions: which homebrew reactions would need them, and how "within N feet" reads without positions ([Live reaction windows](closed/047-live-reaction-windows.md)).
- Dice-valued roll bonuses. Bless, Bane and a homebrew "allies add 1d4 to attack rolls" aura need a modifier that adds a die, and `ModifierChange` has only flat values. The standard party casts none of them. Open: whether the change takes a dice string, how the policy values it, and whether a die counts toward Advantage-style stacking ([Haste extra action and ally-targeted buffs](closed/055-haste-extra-action-and-ally-targeted-buffs.md)).
- Batch value of debuffs. Once modifiers land on their target, a homebrew "the target has Disadvantage on attack rolls" rider or Slow's -2 AC lands on an opponent, and policy v3 scores it 0 because ticket 045 valued buffs only. Monsters built around debuffs read weaker in batch than they play. Open: whether a debuff mirrors the buff formula (the target's threat or incoming damage it changes) and whether that needs a v4 policy ([Haste extra action and ally-targeted buffs](closed/055-haste-extra-action-and-ally-targeted-buffs.md)).
- Seeing Invisible creatures by spell or trait. See Invisibility and homebrew "sees invisible creatures" traits have no effect in the vocabulary, so ADR 0017's sight rule counts only Blindsight and Truesight and the agent overrides the rest. Open: whether it is a trait effect, a timed modifier, or both, and whether the standard party ever casts it ([Align attack-roll condition sources](closed/067-align-attack-roll-condition-sources-with-2024-rules.md)).
- `is_limited` and `usage_word` in `bench-core/src/tactics.rs` still read `slot_level` to tell a leveled cast from a cantrip. A homebrew PC with `spell_slots` whose leveled cast has no slot level would be scored as unlimited. Found by the 059 audit.

## Out of scope

- Non-combat play (story, social, exploration): the tool tests combats and numbers only.
- Items, spells, classes, subclasses, and the prose rules reference: separate future maps. The design should not block them.
- MCP server and long-running server modes: phase 1 is a one-shot CLI. An MCP wrapper can come later over the same commands.
- Agent-written engine code for house rules: phase 1 applies them as prose through overrides. The house rule format leaves room for it.
- Magic items in the standard party: the baseline curve shows no fall-off through level 18, and the High cells at levels 19 and 20 are too thin and too concentrated in a few monsters to change the whole party ([Does the standard party fall off at high levels](closed/052-does-the-standard-party-fall-off-at-high-levels.md)).
- Position-dependent vision: sense ranges measured against range bands, light sources, and who sees whom per pair need positions that abstract engagement doesn't have ([Encounter lighting setting](closed/049-encounter-lighting-setting.md)).
- Engine-played monster turns in live mode (a possible `bench auto-turn` that calls the batch tactics policy): phase 1 has the agent choose every monster action. It can be added over the same step function without changing the live contract.
