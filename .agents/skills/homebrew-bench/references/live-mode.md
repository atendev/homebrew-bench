# Live mode

You are the DM for one encounter. The user controls the party and declares each PC's action. You choose every monster action. `bench` resolves each declared action and holds the state. The honest-output rules in `SKILL.md` apply to every line you narrate.

## Set up

1. **Gather the combatants.** The user's PCs are stat blocks in the same schema as monsters (`bench schema monster`, with `class` and `level` set). Build them from the user's character sheets, or start from a standard party member: `bench party show --level <n>` prints all four, and you save the ones you want as files. Monsters are a homebrew file, or an SRD fixture id from `bench fixture list`. Validate each file with `bench schema validate <file>`.
2. **Agree the settings** with the user:
   - Who rolls PC dice: `--pc-dice ask` for the user's own dice, `--pc-dice engine` for engine rolls.
   - Starting positions: append `@near` or `@far` to a combatant; everyone starts `near` by default. Nobody starts engaged; use `bench move` on the first turns.
   - Surprise: `--surprised <combatant or side id>`, once per id.
   - Lighting: `--lighting <unspecified|dim_light|bright_light|sunlight>` sets one value for the whole encounter, `unspecified` by default. The engine applies `roll_modifier` effects on traits when the lighting meets them, such as a kobold's Sunlight Sensitivity under `sunlight`, to attack rolls and saving throws, and the event names the trait. Sunlight counts as Bright Light. `unspecified` turns no lighting trait on, so pick a value whenever the scene has one.
3. **Start it.**

   ```
   bench start pc-a.json pc-b.json monsters=wyvern-hatchling.json@far --pc-dice ask --seed <n>
   ```

   The side defaults to `party` for stat blocks with a `class` and `monsters` otherwise; prefix `party=` or `monsters=` to set it.
4. **Roll PC initiative.** In ask mode, `bench start` returns `ok` with `pending` set to a d20 prompt for each PC's initiative, and the encounter stays at round 0. Ask the user for each face and answer with `bench respond <face>`, one prompt at a time, until `pending` is empty.

Done when `pending` is empty, `digest.active_turn` names a combatant, and you have told the user the initiative order.

## Run turns

Read `digest.active_turn` after every command. For each turn:

1. **Declare.** On a PC's turn, ask the user what the PC does. On a monster's turn, choose its action from its stat block and say what it attempts.
2. **Resolve, one command per declared action.**
   - `bench move <actor> <engaged|near|far> --target <id>` moves relative to one combatant. Without `--target` the actor moves to that band relative to every other combatant and breaks every engagement it leaves. It costs the largest single-pair change, and dead, unconscious and stable combatants add nothing to the cost. Moving to `engaged` always needs `--target`. `--feet <n>` sets the feet available for the move; it defaults to the remaining walk speed after Speed modifiers (Haste doubles it, Slow halves it, Grappled, Restrained or a Speed 0 effect make it 0). The engine trusts `--feet` and never checks it against Speed, so pass only what the rules allow. A Dash adds the creature's modified Speed (a Hasted 30-foot walker has 60 more feet, a Slowed one 15), a creature at Speed 0 still has 0 after a Dash, and a fly speed the engine doesn't track counts only when the creature has one.
   - The engine doesn't log a spell's agent clauses when it is cast; read them in `data/spells/effects.json`. Slow's targets repeat the Wisdom save at the end of each of their turns, and a success ends Slow on that target: remove each of its Slow modifiers with `bench override active_modifiers.<index> --clear --reason "<why>"`, checking `state` for the indexes after each removal. `digest` lists each combatant's `ranges` and `engagement`.
   - `bench disengage <actor>` is the Disengage action. It spends the action and the actor's moves this turn provoke no Opportunity Attack.
   - An extra action from a modifier (Haste) is spent with `--extra`: `bench action <actor> <action-id> <target-id>... --extra` or `bench disengage <actor> --extra`. It leaves the action unused, and the actor can take it before or after its action. `digest.extra_action` lists the active combatant's uses while one is left, such as `["one_attack", "disengage"]` (`one_attack` is an action that is exactly one single-target attack; `["any"]` allows any action), and is absent otherwise. The engine refuses anything else with the reason. Haste's Dash, Hide and Utilize uses are yours to adjudicate. When Haste ends (concentration breaks or the caster casts another concentration spell), the engine applies its lethargy: the target is Incapacitated with Speed 0 until the end of its next turn.
   - `--opportunity <reactor>[:<attack-id>]` on a move that leaves engagement declares that reactor's Opportunity Attack up front, so it gets no window. Repeat the flag for several reactors; they attack in the order given. See Opportunity attacks below.
   - `bench action <actor> <action-id> <target-id>...` resolves one action, bonus action, or reaction by its id from the stat block, every roll inside it included. Multiattack, spells and saves all go through this command.
   - A `teleport` effect moves its subject: the creature using the ability by default, so `bench action <actor> <teleport-ability>` with no target teleports the actor, or each target when the effect says `"subject": "target"`. The engine clears the subject's engagements and logs `<id> teleports up to <n> feet`; the band it lands at is yours to set with `bench override` if the scene needs one.
   - The engine fails Strength and Dexterity saves on its own, with no die and no prompt, for a Paralyzed, Petrified, Stunned or Unconscious creature and a downed PC, and gives a Restrained creature Disadvantage on Dexterity saves.
   - `bench action <actor> <action-id> <target-id>... --slot <level>` casts a PC's leveled spell with a higher slot when the user picks one. It sets the cast level of every leveled spell in the action and spends that slot. Without it a spell uses the slot its stat block names. The engine refuses the action when the stat block has no `spell_slots`, the action casts no leveled spell, the level is below the spell's level, or no slot of that level is left; the error gives the reason. Monsters cast at the level their stat block names, so don't pass `--slot` for them.
3. **Answer prompts.** When `pending` is set, the encounter waits. `pending.message` says what it needs.
   - A PC dice prompt goes to the user. Pass their natural die faces with `bench respond <face>...`, or `bench respond --decline` to let the engine roll the rest.
   - A `reaction` prompt is a reaction window: `pending.actor_id` may react to a trigger, and `pending.message` names the trigger and the options, such as `goblin-warrior: Opportunity Attack on mia (scimitar)?` or `mia: hit by ogre (attack 15 vs AC 12), take shield?`. A PC's window goes to the user, and a monster's window is yours to decide. Answer with `bench respond --take` to take the one option offered, `bench respond --take <id>` to pick one when several are offered, or `bench respond --decline` to pass. A bad id is refused with the list of options. The engine then runs the held command again from the start with the answer, so its dice come up the same. One command can open several windows, one after another, and dice prompts in between.
   - Until the prompt is answered, only `respond`, `undo`, `override` and read-only commands run.
4. **Narrate** from `events` and `digest` only. Each event carries a ready-made `line`.
5. **End the turn** with `bench end-turn` when the actor is done. It runs end- and start-of-turn effects, recharge rolls and repeat saves, and skips combatants who are dead, unconscious or stable. Other combatants who cannot act, such as a paralyzed one, still get a turn; end it at once.
6. **Legendary actions** happen on the end-turn. Before you end a turn, read `digest.legendary`: it lists each creature that may take one when this turn ends, its `uses_left` and its `ready_actions`. Decide for monsters and ask the user about PCs. Then declare them on the end-turn:

   ```
   bench end-turn --legendary dragon:tail=mia --legendary dragon:wing=mia,theo
   ```

   Each `--legendary <holder>:<action-id>[=<target>,...]` costs one use, and they resolve in the order given, after this turn ends and before the next starts. The creature whose turn is ending can't take one; the creature whose turn comes next can. The engine refuses the whole end-turn when a declaration is not allowed: the holder can't act, has no uses left, or the action is not recharged, is on cooldown, or has no uses left today. The error gives the reason. A holder that drops partway loses its remaining uses (a `legendary_lost` event). An unmodeled legendary action still spends its use; resolve its text yourself after the command returns. The engine charges one use per legendary action. For one that costs more, record the extra with `bench override <holder>.resources.<holder>:legendary <used> --reason "<why>"`. Lair actions have no engine support. `bench undo` reverts the end-turn and its legendary actions together.

When the user asks to take a turn back, run `bench undo`; it reverts one command and restores its dice. For anything larger, use an override with a reason.

## What the engine leaves to you

Each of these is agent judgment. Label it, then record it through `bench roll <dice> --reason "<why>"` for the dice and `bench override <path> <value> --reason "<why>"` for the result.

- **Agent clauses and unmodeled abilities.** `bench action` runs only an ability's `effects`. Before you resolve one, check its `kind` and `agent_clauses` in the stat block, and apply any text the effects leave out after the command returns. A spell missing from the effects file comes back as an `unmodeled_cast` event; resolve that spell yourself. An `upcast_clause` event (`<actor> casts <spell> at level <n>; agent clause: <text>`) means the engine resolved the spell at that level but could not apply the text; apply it yourself.
- **Reactions.** The engine opens reaction windows for Opportunity Attacks and for hits by an attack roll, the latter for any reaction with a hit trigger, such as Shield and Parry (see Answer prompts). Every other trigger is yours: when a spell is cast, a creature moves near, or Shield's Magic Missile clause applies, ask the user whether a PC reacts and decide for monsters. Run that reaction with `bench action <actor> <reaction-id> <target-id>` out of turn. When a taken reaction has agent clauses, the engine prints each as an `agent_clause` event (`<reactor> <name>, agent clause: <text>`) after the `attack_rechecked` line, which says whether the attack still hits. Resolve the clause from that line: Riposte's extra attack happens only if the recheck reads `(miss)`.
- **Opportunity attacks.** The engine rolls them. A move that leaves a creature's reach opens a `reaction` window for each creature that could react, in initiative order, before any attack resolves. Ask the user about each PC's window and decide each monster's. `--take` uses the first option, the reactor's first at-will melee attack; `--take <attack-id>` names a different melee attack, such as a limited-use one. Nothing provokes when the mover took Disengage or has Flyby or Agile. You can still declare an attack up front with `bench move <actor> <band> --opportunity <reactor>[:<attack-id>]`, which skips that reactor's window. The attacks resolve right before the move. If one leaves the mover unable to act, the move stops (a `move_stopped` event) and no movement is spent.
  The engine refuses the whole move when a named reactor can't react: it is on the mover's side, can't act, can't take reactions, has already used its reaction, can't see the mover (ADR 0017: an Invisible mover is hidden unless the reactor has Blindsight or Truesight, and a Blinded reactor sees only with Blindsight), the mover took Disengage this turn or has Flyby or Agile, or the move doesn't leave its reach. The error gives the reason. A declined window leaves no event about that creature, and the public view hides the window. With `pc_dice = ask`, a PC reactor's dice pause the move on a dice prompt like any PC roll. The reaction comes back at the start of the reactor's own turn.
- **Lighting the engine doesn't hold.** When the light changes mid-fight (dawn, a Daylight spell, the fight moving outdoors), run `bench override settings.lighting <value> --reason "<why>"`; `bench undo` reverts it. Darkness, light sources such as a torch or a fire elemental, and one creature standing in different light from the rest stay your judgment. `digest.lighting` shows the current value, also in the public digest.
- **Terrain, cover**, and every ruling the ruleset leaves open.

Override paths are dotted over the state, such as `goblin-2.hp 14` or `mia.conditions '["prone"]'`. Use `--clear` to remove a value, `--standing` when the call should hold for the rest of the fight, and `--rule <slug>` when a house rule drove it. Add or remove combatants with `bench add <file or fixture id> --side monsters --band near` and `bench remove <id> --reason "<why>"`.

The engine reads engagement for position-worded condition rules but doesn't check it before a melee attack. Combatants start `near`, so a melee attack resolved without `bench move <actor> engaged --target <id>` first gives the attacker Disadvantage against a Prone target and no automatic critical hit against a Paralyzed or downed one. Engage first. When you set a condition by override, name the grappler or the source of fear in its `source`, such as `mia.conditions '[{"condition": "grappled", "duration": "permanent", "source": "ogre"}]'`, because the engine reads it: a Grappled creature rolls straight only against its `source`, and a Frightened one has Disadvantage only while it sees its `source`. A downed PC counts as Unconscious and Prone for attacks. Prone and the automatic critical hits on Paralyzed and Unconscious targets read "within 5 feet" as engaged. A ranged attack by an engaged creature has Disadvantage, and the attack event says `(Disadvantage: ranged attack in close combat)`, unless every enemy engaged with it can't see it or is Incapacitated. To shoot without it, `bench move` the shooter out of engagement first, which may provoke Opportunity Attacks; `bench disengage` avoids them but spends the action. An attack with both reach and range, such as a thrown dagger, counts as melee against a target the attacker is engaged with and as ranged against any other. See Invisibility and a "sees invisible creatures" trait are your judgment: remove the Invisible condition by override for that attack.

## Showing players

`bench state --public` and `bench log --public` hide monster hit points, resources, recharge and damage amounts and show wounded states instead. Use the public versions for anything the user should see as a player, and the full versions for your own DM decisions.

## End

A live encounter runs until you end it. When one side is dead, fled or surrendered, or the user calls it, run `bench end --reason "<why>"`. Offer the user `bench log` for the full record and `bench replay` to recheck every state hash. `bench list` shows earlier encounters. Every live command after `bench start` takes `--encounter <id>`, placed after the command name, to target one of them; without it the command acts on the most recently started encounter that is still running.
